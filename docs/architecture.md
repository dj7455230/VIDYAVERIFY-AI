# VIDYAVERIFY AI — Architecture

## Overview

VIDYAVERIFY AI is a full-stack platform for APAAR ID-based student data management and verification, built for Smart India Hackathon problem statement SIH26263.

## Key Design Decisions

### 1. Evidence-First Approach
Every risk score, duplicate candidate, and investigation case is backed by evidence references stored in the database. The platform never labels a student or institution as "fraudulent" based on a score alone.

### 2. Server-Side Authorization
All authorization is enforced on the backend. Frontend role checks only control UI visibility — they do not grant access. Every API endpoint validates the user's role and institution scope before returning data.

### 3. Institution-Level Data Isolation
Institution admins can only access data for institutions they are assigned to via `institution_user_memberships`. This is enforced in every database query.

### 4. Synthetic Data Only
All seed data is generated by a deterministic script using fictional names, fictional institutions, and fictional APAAR references. No real student records are stored or processed.

### 5. Simulated Verification
The verification provider (`DEMO_SIMULATOR`) returns fictional outcomes. The architecture supports adding a real provider via an adapter interface, but no official APAAR/AICTE endpoints are used or claimed.

### 6. Explainable Risk Scoring
Risk scores (0-100) are calculated by a deterministic function with configurable, documented weights. Every score includes contributing factors, evidence references, and a full history of changes.

## Component Breakdown

### Backend Modules
- `app/config.py` — Environment configuration
- `app/database.py` — SQLAlchemy engine and session factory
- `app/models/` — 23 database models
- `app/security/` — JWT auth, password hashing, role dependencies
- `app/api/v1/` — 18 API route modules
- `app/schemas/` — Pydantic request/response validation
- `scripts/seed_demo_data.py` — Deterministic synthetic data generator

### Frontend Modules
- `src/lib/api.ts` — API client with JWT auth
- `src/contexts/AuthContext.tsx` — Authentication state
- `src/components/Sidebar.tsx` — Role-aware navigation
- `src/features/dashboard/` — AICTE Command Centre
- `src/app/` — 14 route pages (App Router)

## Data Flow

```
User → Frontend (form/table) → API (JWT + role check) → Database query (scope filter) → Response
```

Every API request:
1. Validates JWT token
2. Checks user is active and not locked
3. Verifies role permission for the endpoint
4. Applies institution scope filter where applicable
5. Executes parameterized database query
6. Returns response with appropriate data minimization
7. Logs significant actions to the append-only audit log
